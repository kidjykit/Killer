# Killer — คิลเลอร์เกม

เว็บแอปสำหรับเล่นเกมปาร์ตี้แนวจิตวิทยา **Killer** ตามกติกาใน [`rule.md`](./rule.md)
เล่นได้ทั้ง **ออนไลน์** (สร้างห้อง แชร์ลิงก์ให้เพื่อน) และ **ออฟไลน์** (ใช้มือถือเครื่องเดียวแทนสำรับไพ่)
ภาษาไทยทั้งหมด ธีมขาว–ดำสลับตามกลางวัน/กลางคืน

## สแตก

- **Frontend** — React 18 + TypeScript + Vite + React Router (ไม่มี UI framework, CSS เขียนเอง)
- **Backend** — Cloudflare Workers + **Durable Objects** (1 ห้อง = 1 Durable Object) ผ่าน WebSocket
- **Deploy** — Cloudflare Workers พร้อม static assets (ไฟล์เดียวจบ ไม่ต้องแยก Pages)
- **Test** — Vitest ทดสอบ game engine ที่เป็น pure function

Durable Objects ที่ใช้เป็นแบบ **SQLite-backed** ซึ่งใช้ได้ทั้งแผนฟรีและแผนเสียเงินของ Cloudflare

## โครงสร้างโปรเจกต์

```
src/

    roles.ts       นิยามบทบาท, ตารางจำนวนไพ่ 6–12 คน, สร้าง/สับกองไพ่
    engine.ts      pure function: คิดผลกลางคืน, นับโหวต, เช็กเงื่อนไขชนะ
    __tests__/     เทสต์ครอบตารางผลลัพธ์ใน rule.md
  worker/
    index.ts             routing + สร้างรหัสห้อง + เสิร์ฟ static assets
    RoomDurableObject.ts สถานะห้อง, WebSocket, ตัวจับเวลา (alarm), การกรองข้อมูลลับ
  client/
    pages/         HomePage, RoomPage (ออนไลน์), OfflinePage, PrintPage
    components/    CardTable, PlayingCard, Lobby, PhasePanels, Chat, ModeratorNotes

    styles/        theme.css — ธีมขาว–ดำ สลับด้วย data-mood ที่ <html>
```

## รันในเครื่อง

ต้องเปิด 2 เทอร์มินัล เพราะ Vite ทำหน้า UI ส่วน Worker ทำ API/WebSocket

```bash
npm install

# เทอร์มินัลที่ 1 — Worker + Durable Object (port 8787)
npm run cf:dev

# เทอร์มินัลที่ 2 — Vite dev server (proxy /api ไปที่ 8787)
npm run dev
```

หรือจะรันแบบ production ในเครื่องเลยก็ได้ (Worker เสิร์ฟทั้ง UI และ API จากพอร์ตเดียว):

```bash
npm run build && npm run cf:dev   # เปิด http://127.0.0.1:8787
```

คำสั่งอื่น ๆ

```bash
npm test         # รันเทสต์ game engine
npx tsc -b       # typecheck ทั้ง client และ worker
npm run build    # build UI ลง dist/
```

## Deploy ขึ้น Cloudflare

```bash
npx wrangler login
npm run cf:deploy       # = npm run build && wrangler deploy
```

`wrangler.toml` ตั้งค่าไว้ครบแล้ว — Durable Object binding, migration และ SPA fallback
ครั้งแรกที่ deploy Cloudflare จะสร้าง Durable Object namespace ให้เอง

## วิธีเล่นออนไลน์

1. กด **สร้างห้องใหม่** → ได้รหัสห้อง 5 ตัว เช่น `K7M2Q`
2. คัดลอกลิงก์ส่งให้เพื่อน ทุกคนใส่ชื่อเล่นแล้วเข้าห้องเดียวกัน
3. เจ้าของห้องตั้งกติกาในล็อบบี้ แล้วกด **เริ่มเกม — แจกไพ่**
4. ทุกคนแตะกองไพ่กลางโต๊ะเพื่อจั่วการ์ดของตัวเอง (การ์ดพลิกโชว์เฉพาะเจ้าตัว)
5. พิธีกรกด **เข้าสู่คืนที่ 1** แล้วเดินตามบทที่แอปขึ้นให้ทีละขั้น
6. ตอนกลางวันแอปประกาศผล → อภิปราย → โหวต → วนไปจนจบเกม

### โหมดพิธีกร

- **คนจริงเป็นพิธีกร** (ค่าเริ่มต้น) — พิธีกรไม่ได้รับไพ่ เห็นบทบาททุกคนบนโต๊ะ เห็นสถานะว่าใครกดแล้ว
  และเป็นคนกดเดินเกมเอง ได้ **สมุดบันทึกพิธีกร** ที่สรุปทุกคืนให้ครบ
- **ระบบเป็นพิธีกรอัตโนมัติ** — ทุกคนได้รับไพ่และได้เล่น แอปนับเวลา เรียกบทบาท คำนวณผล และประกาศเอง
  ไม่มีใครเห็นบทบาทคนอื่นเลย

### สมุดบันทึกพิธีกร

จบทุกคืนแอปจะสรุปให้พิธีกรอ่าน พิธีกรไม่ต้องจำเอง เช่น

```
🌙 สรุปคืนที่ 1
  🔪 Killer เลือกฆ่า: เอ
  🔍 ตำรวจสืบ: อี → ชี้ถูก! คนนี้คือ Killer
  🕯️ แม่ชีรักษา: เอ → ❌ เป็นโมฆะ เพราะแม่ชีศีลขาด
  🥷 โจรปี้: ดี → ⚠️ โดนตัวแม่ชี! แม่ชีศีลขาด รักษาไม่ขึ้นทั้งคืน
  📣 ผลสรุป: คืนนี้ เอ เสียชีวิต
```

## ความเป็นส่วนตัวตอนกลางคืน

ตอนกลางคืนแอปตั้งใจ "ปิดตา" ผู้เล่นให้เหมือนหลับตาจริง ๆ

- ผู้เล่นทั่วไป **ไม่ได้รับข้อมูลลับตั้งแต่ชั้น server** ไม่ใช่แค่ซ่อนใน UI — บทบาทของคนอื่น
  สมุดบันทึกพิธีกร ตัวเลือกของ Killer และผลการสืบของตำรวจ ถูกกรองออกใน `viewFor()` ก่อนส่ง
- ซ่อนไฟสถานะออนไลน์ของผู้เล่นทุกคน เหลือแค่พิธีกรที่เห็น เพื่อไม่ให้เดาได้ว่าใครกำลังทำอะไร
- ห้ามพิมพ์ในห้องแชทหลักตอนกลางคืน
- โหมดอัตโนมัติจะเดินครบเวลาทุกขั้นเสมอ **ไม่ตัดจบเร็วแม้ทุกคนกดแล้ว** เพราะความเร็วในการจบขั้น
  จะกลายเป็นเบาะแสว่าบทบาทนั้นตายไปแล้ว

เมื่อเพิ่มวิดีโอ/เสียงเข้ามา จุดนี้จะขยายเป็นการ **บังคับ mute และปิดกล้องทุกคนตอนกลางคืน**
(เลือกไว้แล้วตอนออกแบบ) เหลือเฉพาะพิธีกรที่เห็นสถานะ

## โหมดออฟไลน์

- **แจกการ์ด** (`/offline`) — ใส่ชื่อผู้เล่น สับไพ่ แล้วส่งมือถือต่อกันไปทีละคน
  แต่ละคนแตะเปิดดูไพ่ของตัวเอง อ่านหน้าที่ แล้วกดปิดก่อนส่งต่อ มีหน้า "เฉลยทั้งหมด" สำหรับพิธีกรแยกต่างหาก
- **ตารางสรุป 1 หน้า** (`/print`) — A4 แนวตั้ง พิมพ์หรือบันทึกเป็น PDF ได้จากเบราว์เซอร์
  มีครบทั้งตารางบทบาท จำนวนไพ่ 6–12 คน บทพิธีกร ตารางคิดผลกลางคืน เงื่อนไขชนะ และมารยาทการเล่น

## แผนต่อไป

**วิดีโอ/เสียง** — ยังไม่ทำใน v1 ระหว่างนี้ใช้ Discord/LINE คู่ขนานไปก่อน
เมื่อจะทำ มีทางเลือกหลัก 3 ทาง คือ P2P mesh WebRTC (ถูกที่สุด ดีที่ 6–8 คน),
Cloudflare Realtime SFU (อยู่ใน ecosystem เดียวกัน ลื่นถึง 12 คน) และ LiveKit Cloud (SDK สำเร็จรูป)
โครงสร้างปัจจุบันรองรับอยู่แล้ว เพราะ `privacyLock` และ `actingPlayerIds` ใน `RoomView`
ถูกออกแบบมาให้ชั้น A/V อ่านไปสั่ง mute/ปิดกล้องได้เลย

สิ่งอื่นที่ยังทำได้อีก — เสียงประกอบกลางวัน/กลางคืน, สถิติผู้เล่น, บทบาทเสริม,
และบันทึกประวัติการเล่นย้อนหลัง
